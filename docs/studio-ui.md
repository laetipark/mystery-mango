# 제작 작업실과 반응형 화면

## 참고와 적용 기준

제작 흐름은 [Tabletopia의 구성물·게임판 배치](https://help.tabletopia.com/knowledge-base/how-to-create-a-game/), [PlayingCards.io의 도구함·선택 옵션](https://playingcards.io/docs/edit-general), [Arcweave의 인물·단서 구성물](https://docs.arcweave.com/project-items/components), [Twine의 이야기 지도](https://twinery.org/reference/en/editing-stories/navigating.html)를 참고한다. 망고보드 공유 편집기를 Chrome 확장으로 열어 상단 저장 도구, 좌측 도구함, 중앙 캔버스와 레이어 패널을 확인했다. 참고 서비스의 그림이나 소스를 복사하지 않으며 서비스용 아이콘과 템플릿 그림을 직접 작성한다.

## Studio v2 작업실

2026-10-06 사용자가 제공한 `mystery-mango-studio-v2.html`·설계 문서·화면 3개를 기준으로 제작 화면을 재구성했다. 첨부의 모의 데이터나 로컬 저장 코드를 이식하지 않고, 기존 작가 API·초안·실제 게임 엔진에 새 화면을 연결한다.

상단은 차콜 배경에 Mystery Mango 브랜드, 내 작업·플레이·파일, 작품명, 저장 상태, 실행 취소·다시 실행·저장·미리보기·시험 플레이·공개 준비를 둔다. 편집기에서는 일반 사이트 머리글을 중복 표시하지 않는다. 저장 상태는 변경됨·저장 중·저장됨·실패·충돌을 구분하며 파일 메뉴에서 편집 사본을 내려받는다. 기존 자체 호스팅 Pretendard와 원본 라이선스는 유지한다.

작업 단계는 **꾸미기 / 게임 설정 / 테스트 / 공개 준비**다. 첫 진입은 자유 테이블의 게임판, 머더미스터리의 이야기 흐름, 자동 게임의 디자인이다. 이후 같은 작품에서는 마지막 편집 위치로 돌아간다. 왼쪽 레일에서 템플릿·게임판/이야기·요소·텍스트·배경·자료·카드 디자인·업로드·게임 규칙·기본 정보로 이동한다. 유형에 필요한 도구만 제공하며 게임판은 실제 테이블 구성물 또는 자동 게임의 색상 디자인을 편집한다. 화면 장식과 실제 게임 구성물을 혼동하지 않도록 분리한다.

넓은 작업 영역은 **왼쪽 구성 목록 + 중앙 캔버스 + 오른쪽 속성 + 보조 도구**다. 요소를 골라도 구성 목록을 함께 볼 수 있으며 각 패널은 독립적으로 스크롤한다. 요소·텍스트·배경 도구를 바꾸어도 현재 카드와 앞뒷면, 선택·배율을 유지한다. 재료 목록·속성 버튼은 선택을 유지하며 패널만 전환하고, **선택 해제** 또는 Escape는 선택을 해제하고 재료 목록 버튼으로 초점을 돌려준다. 레이어는 오른쪽 버튼에서 필요한 동안 띄우며 잠금·숨김은 제작 편의 기능이다. 캔버스 하단에는 실제 장면별 썸네일과 순서·추가 도구를 배치한다. 장면 선택·정렬은 게임 진행 단계를 변경하지 않는다.

텍스트·이미지·도형·자료를 선택해 기존 지원 필드만 편집한다. 새 텍스트는 배경 밝기에 맞는 기본색을 사용하고, 기존 작품의 색은 바꾸지 않는다. 저장 계약이 없는 글꼴·굵기·임의 권한 설정을 저장되는 기능처럼 제공하지 않는다. 카드 앞면·뒷면 전환과 동일 디자인 연결은 기존 서버 규칙을 유지한다.

게임 설정의 이야기 화면은 순차 단계와 엔딩 분기를 연결도로 표시한다. 단계 재정렬, 역할·단서·조사 대상·조건·효과의 기존 폼을 그대로 사용하며 자유로운 그래프 연결이나 새로운 규칙 실행을 추가하지 않는다. 엔딩은 배열 순서대로 처음 충족하는 항목을 고르는 기존 판정을 설명한다.

테스트 단계에서 저장한 버전을 고정해 혼자 시험하거나 친구와 초대 시험을 한다. 머더미스터리의 **역할별 자료 비교**는 작품 소유자에게 허용된 시험 API를 자리별로 조회해 비밀·현재 단서·공개 자료를 나란히 표시한다. 프런트가 초안으로 열람 범위를 추측하지 않는다. 일반 플레이 화면에는 역할 전환이나 비교 도구가 없다. 공개 준비에서는 작품 정보·검증·검수 제출·버전 이력을 확인하며 관리자의 기존 승인 흐름을 유지한다.

한 작품의 소개·규칙·장면·카드 디자인은 같은 초안과 되돌리기 이력을 사용한다. 템플릿 갤러리에서 다른 템플릿을 고르면 현재 초안을 저장한 뒤 **별도의 새 작품**을 생성한다. 현재 작품의 유형이나 내용을 덮어쓰지 않으며 저장 실패·충돌은 새 작품 생성 창 안에도 표시한다.

### 기본 템플릿과 빈 템플릿

스튜디오 보관함에서 여섯 게임 유형의 기본 템플릿 또는 빈 템플릿을 선택한다. 기본 템플릿은 예시 문구·구성물을 포함하고, 빈 템플릿은 같은 편집기에서 처음부터 내용을 추가한다. 빈 템플릿에도 선택한 게임 유형과 고정 엔진·지원 인원·기본 색상은 유지한다. 자동 게임의 빈 템플릿은 임의 규칙 편집기가 아니다.

빈 머더미스터리에서는 왼쪽 구성 목록의 추가 버튼으로 첫 항목을 만들면 해당 속성이 열린다. 단계를 추가한 뒤 종류와 허용 행동을 설정하고, 역할·단서·조사 장소를 만든 뒤 이름 선택으로 연결한다. 범인 투표의 범인 역할은 처음에는 선택되지 않는다. 빈 자유 테이블에서는 구성물 추가 버튼으로 실제 카드·말·주사위·카운터·덱을 배치한다. 덱 카드는 목록에서 추가하고 순서를 바꾸며, 카드 디자인은 앞면과 뒷면을 별도로 편집한다.

모든 빈 템플릿의 **장면·자료**에는 요소가 없는 공용 장면 하나가 있다. 이 장면에서 텍스트·이미지·도형을 추가하거나 배경색을 바꿀 수 있고, 미리보기는 빈 배경도 그대로 보여 준다. 카드 디자인 목록도 비어 있으므로 첫 디자인은 **카드 디자인 추가** 또는 구성물 속성의 디자인 버튼으로 만든다. 초안은 미완성이어도 저장하지만 소개와 게임별 필수 내용을 채워 검증을 통과하기 전에는 시험·검수를 시작하지 않는다. [유형별 시작 순서](studio.md#빈-템플릿으로-시작하기)를 따른다.

모바일에서는 같은 빈 초안을 확인할 수 있다. 첫 항목 추가·배치·규칙 연결은 기존 정책대로 PC에서 진행하며, 만들어 둔 내용의 문구·색상·이미지를 모바일에서 바꿀 수 있다.

## 카드 앞뒷면

`presentation.cardLayouts`에 이름·논리 크기·앞뒷면을 저장한다. 면에는 배경색과 텍스트·이미지·사각형·타원 요소가 들어간다. 공용 카드는 `layoutId`로 앞뒷면을, 덱 카드는 `layoutId`로 앞면을 연결한다. 덱의 `backLayoutId`는 해당 디자인의 뒷면을 공통으로 사용한다. 덱에서 뽑힌 카드는 기존 120×170 크기를 유지한다.

지정된 디자인이 있으면 기존 문구·이미지 위에 중복 표시하지 않는다. 지정된 빈 디자인은 빈 면이며, 연결이 없는 기존 카드만 기존 이미지·문구 표시를 사용한다. 잘못된 디자인 참조는 완전 검증에서 거부한다. 디자인은 고정 버전 안에 보관되며 이후 초안 수정은 이미 시작한 게임을 바꾸지 않는다.

실제 참가자에게는 공개 상태와 소유 좌석에 따라 선택한 면의 `faceDesign`만 전달한다. 덱에는 `backDesign`만 전달한다. 작성용 레이아웃 목록·앞뒤 두 면·편집용 요소 ID·레이아웃 연결은 보내지 않으며, 현재 게임의 구성물을 조작하는 ID는 유지한다. 실제 게임과 샌드박스, 파일 다운로드 검사가 같은 Java 투영을 사용한다. 손패를 다른 참가자에게 옮기면 이후 응답에서 기존 소유자의 앞면을 제거한다. 이미 정당하게 열람한 정보를 상대의 기억이나 브라우저에서 회수하는 기능은 아니다.

카드 디자인 자산도 작품 소유권·버전 참조·파일 삭제 방지 검사에 포함한다. 편집용 잠금·레이어 숨김은 실제 비밀 공개 권한을 대체하지 않는다.

### 카드 레이아웃 JSON 예제

다음은 자유 테이블 작품의 `presentation`과 `tabletop` 부분을 보여 주는 예제다. 전체 작품을 새로 등록하는 요청 본문은 아니며, 작품 제목·유형·지원 인원 등 다른 필드는 기존 문서를 유지한다. 기존 장면이 있다면 `scenes`도 보존한다. 화면에서 편집한 내용은 이 구조로 저장되므로 JSON을 직접 입력할 필요는 없다.

```json
{
  "presentation": {
    "scenes": [],
    "cardLayouts": [
      {
        "id": "green-card",
        "name": "초록 카드",
        "width": 600,
        "height": 850,
        "front": {
          "background": "#fffaf0",
          "nodes": [
            {
              "id": "front-title",
              "kind": "TEXT",
              "x": 60,
              "y": 80,
              "width": 480,
              "height": 160,
              "rotation": 0,
              "fill": "#264d3e",
              "text": "이번 차례에 한 칸 이동하세요.",
              "fontSize": 40,
              "locked": false,
              "hidden": false
            }
          ]
        },
        "back": {
          "background": "#264d3e",
          "nodes": [
            {
              "id": "back-mark",
              "kind": "ELLIPSE",
              "x": 180,
              "y": 305,
              "width": 240,
              "height": 240,
              "rotation": 0,
              "fill": "#e8c58c"
            }
          ]
        }
      }
    ]
  },
  "tabletop": {
    "objects": [
      {
        "id": "public-card",
        "kind": "CARD",
        "name": "공용 이동 카드",
        "text": "디자인 연결이 없을 때 사용할 문구",
        "assetId": null,
        "backAssetId": null,
        "layoutId": "green-card",
        "x": 80,
        "y": 100,
        "width": 120,
        "height": 170,
        "locked": false,
        "faceUp": false
      }
    ],
    "decks": [
      {
        "id": "move-deck",
        "name": "이동 카드 덱",
        "x": 280,
        "y": 100,
        "backAssetId": null,
        "backLayoutId": "green-card",
        "cards": [
          {
            "id": "move-one",
            "name": "한 칸 이동",
            "text": "디자인 연결이 없을 때 사용할 문구",
            "assetId": null,
            "layoutId": "green-card"
          }
        ]
      }
    ]
  }
}
```

공용 카드는 처음에는 초록 배경의 원이 있는 뒷면으로 보인다. 뒤집으면 앞면 문구가 보인다. 덱도 같은 뒷면을 사용하고, 뽑은 카드는 소유자의 손패에서 앞면으로 보인다. 이 예제의 공용 카드와 덱 카드는 같은 디자인을 참조하므로 초안에서 그 디자인을 수정하면 두 곳 모두 바뀐다. 각각 다른 문구가 필요하면 디자인을 따로 연결한다. 고정한 버전의 디자인은 이후 초안 수정의 영향을 받지 않는다.

이미지를 넣으려면 `kind: "IMAGE"` 요소에 업로드 결과의 실제 `assetId`와 좌표·크기·회전을 넣는다. 외부 이미지 URL을 직접 넣는 필드는 없다. 카드 요소에 역할·단서 바인딩을 넣지 않으며, 앞면의 열람 범위는 게임 중 소유 좌석과 공개 상태가 결정한다. 배경만 있는 면을 원하면 해당 면의 `nodes`를 `[]`로 저장한다. 기존 카드 표시로 돌아가려면 구성물의 `layoutId` 또는 덱의 `backLayoutId` 연결을 해제한다.

정확한 필수 필드·제한은 [작품 정의의 카드 디자인 계약](scenarios.md#카드-디자인-계약)을 따른다.

## PC와 모바일

- 1,200px 이상: 72px 도구 레일·230~280px 구성 목록·가변 작업 영역·260~310px 속성·48px 보조 도구를 함께 표시한다. 좌우 패널의 제목은 각 스크롤 영역 위에 고정한다.
- 801~1,199px: 구성 목록(260px) 또는 오른쪽 속성(280px) 중 하나를 작업 화면과 함께 표시한다. 보조 도구에서 선택을 유지하며 전환하고, 작업 화면 넓히기로 양쪽 패널을 접을 수 있다.
- 800px 이하: 가로 도구 레일과 구성 / 작업 화면 / 속성 전환으로 한 번에 하나의 패널을 사용한다. 기존 문구·색상·이미지 교체와 시험을 제공하고 정교한 배치·규칙 연결은 PC에서 작업하도록 안내한다.

화면 폭을 바꾸어도 같은 편집 요소·면·배율을 유지한다. 폼과 작업 영역에는 최소 너비 제한을 풀고, 긴 이름·도구 행은 패널 안에서 줄바꿈한다. 확대된 캔버스와 긴 목록의 스크롤은 해당 영역에서 처리한다. 카드 상단의 검색·선택·이름·이전/다음 도구는 하나의 제어 영역으로 묶어 작업 공간을 확보한다.

실제 모바일 플레이는 모든 게임의 기존 행동을 제공한다. 자유 테이블은 구성물 선택 목록과 위치 지정을, 요트는 내 점수 기록과 전체 점수판 전환을, 고전 게임은 전체 보기와 확대 보기를 제공한다. 머더미스터리는 역할·진행·대화로 전환한다. 게임판 확대가 문서 전체의 가로 넘침으로 이어지지 않게 한다.

탐색·모집·계정에는 같은 글자·간격·버튼 기준을 적용한다. 모바일 주요 메뉴는 하단에 두고 상세 탐색 조건은 펼쳐서 사용한다. 주요 조작은 44px 이상의 터치 영역, 키보드 이동과 눈에 보이는 초점을 제공한다. 제작·플레이 상태나 권한 판정은 화면 너비에 따라 달라지지 않는다.

검증 결과와 실제 운영 반영 여부는 [검증 기록](verification.md)을 따른다.


## 홈페이지와 편집 동선 (2026-10-17)

[망고보드 홈페이지](https://www.mangoboard.net/)와 [공유 편집기](https://www.mangoboard.net/edit/56182387)의 여백·밝은 소개 화면·차콜 작업 바닥을 참고했다. 미스터리 망고의 자체 `GameArt`와 공개 API 자료를 사용한다. 홈페이지는 큰 중앙 제목, 만들기/탐색, 여섯 게임 종류, 실제 공개 작품 6개, 제작 소개, 이용 흐름 순서다. 콘텐츠는 최대 1,280px이고 모바일 안전 영역과 기존 하단 메뉴를 유지한다. 익명 홈페이지는 작가 템플릿 API를 호출하지 않는다.

게임 종류 카드는 `/scenarios?gameType=...`로 연결하며 모든 탐색 조건은 URL에 저장한다. 새로고침과 뒤로 가기에서 조건을 복원하고 잘못된 값은 정리한다. 로딩·오류·빈 공개 목록도 별도 안내한다. 자동 매칭의 보드게임 목록은 다섯 유형의 전체 페이지를 순회하고 이름으로 검색한다. 직접 전달한 작품은 상세 API로 독립 조회하므로 처음 50개 제한을 받지 않는다. 일부 목록을 받지 못하면 불완전한 목록임을 표시하고 재시도한다. 신청한 뒤에는 티켓의 버전·인원·방식을 사용한다.

카드 편집 상단에 게임판/덱/카드/면 경로와 게임판 복귀가 있다. 공통 디자인을 사용하는 구성물을 이름으로 표시하고 해당 속성으로 이동한다. 카드·덱·디자인·역할·단서·장면은 검색·종류 필터 또는 이전/다음 이동을 제공한다. 역할과 단서는 연결 자료지를 여러 개 만들고 선택할 수 있으며, 자료지에서 역할·단서·단계로 돌아간다. 장면 요약에는 종류·단계·연결 자료·BGM 이름이 있다. 음원 미리듣기는 재생을 누를 때 시작한다.

속성은 내용·모양·배치·연결·레이어로 묶는다. 캔버스에 초점을 두고 방향키로 1px, Shift와 함께 10px 이동한다. 10px 격자 맞춤은 선택 사항이고 작품 데이터에는 저장하지 않는다. 입력창·한글 조합 중에는 캔버스 단축키를 처리하지 않는다. 카드 면을 바꿔도 실제 카드 크기를 변경하지 않는다.

작품별 마지막 대상·면·검색·배율·패널·스크롤은 브라우저의 UI 상태로 저장하며 서버 개정과 되돌리기를 만들지 않는다. 모바일은 상단 저장 도구를 유지하고 카드 목록/이름은 접어 둘 수 있다. 속성 위에는 선택한 카드/자료의 작은 미리보기를 표시한다. 주요 조작은 44×44px 이상이며 입력 글자는 16px이다.

홈의 제작 소개에서는 카드 디자인·게임판·이야기 흐름 예시를 탭으로 전환한다. 예시는 직접 작성한 그림과 안내 문구이며 공개되기 전 작품의 자료를 조회하지 않는다. 방향키·Home·End로 탭을 전환할 수 있다.
