# 상태 전이와 권한

## 로그인과 계정

운영 `prod` 프로필에서는 카카오 로그인으로 가입·로그인을 처리하고 이메일·비밀번호 API는 사용하지 못한다. 개발·E2E에서는 기존 테스트 계정 흐름을 유지한다. 카카오 회원번호를 고유 식별자로 사용하며 이메일 일치로 계정을 자동 합치지 않는다. 이메일·비밀번호와 카카오 액세스·리프레시 토큰은 카카오 신규 계정에 저장하지 않는다. 닉네임을 받지 못하면 기본 이름을 사용한다.

로그인 시작은 현재 세션의 CSRF 토큰으로 보호한다. 콜백은 세션에 묶인 유효기간 있는 일회용 `state`를 검증한다. 외부 토큰 교환은 업무 DB 잠금 밖에서 수행하고, 사용자 생성은 Commands 트랜잭션 아래에서 처리한다. 인증 성공 시 세션 식별자와 CSRF 토큰을 갱신하며 이동 주소는 서비스 내부 경로로 제한한다. Discord 연결은 카카오로 로그인한 서비스 회원에 귀속한다.

## 모집·매칭

활동은 `IDLE → QUEUED → PROPOSED → ROOM → GAME → IDLE`를 따른다. 작품 선택형은 IDLE에서 ROOM으로 이동한다. 동시 요청의 승자는 DB 트랜잭션으로 결정되고, 이미 방이 확정된 티켓 취소는 `ACTIVITY_MOVED`로 실패한다. 프런트는 활동을 다시 조회한다.

머더미스터리 방은 작품의 `playerCount`(1~4명)를 정원으로 사용하고 정확한 인원이 모두 준비해야 시작한다. 1인 작품은 방장 혼자 준비한 뒤 시작할 수 있다. 머더미스터리 자동 매칭의 정원은 4명으로 유지하며 1~3인 작품은 후보에서 제외한다. 보드게임은 `supportedPlayerCounts` 중 방장이 정원을 선택하며, 자동 매칭은 공개 버전·유형·2~4명·대화 방식·언어가 같은 티켓끼리 묶는다. 전원 수락하면 후보 투표 없이 방을 만들며 작품 노출 이력은 보드게임 재참가를 제한하지 않는다. 각 게임 조건의 대기열을 따로 탐색해 다른 게임의 불성립 그룹이 뒤 게임을 막지 않는다. 작품이 지원하지 않는 텍스트·Discord 방식으로 방을 만들 수 없다.

초대방은 공개 목록에서 제외한다. 링크만으로 자료를 읽을 수 없고 로그인·참가 검사를 거친다. 방장 퇴장 전 승계는 joined_at/user_id 순이며 빈 방은 종료한다. 게임 시작 후 충원과 역할 교체는 없다.

초대 링크 토큰은 브라우저가 보안 난수 32바이트로 생성한다. 서버는 해시·24시간 만료만 저장하고 멱등 응답에도 원문을 남기지 않는다. 방장의 화면 메모리에만 링크가 남으므로 새로고침 후에는 새 링크를 발급한다. 초대받은 브라우저는 로그인 복귀에 필요한 토큰을 해당 탭의 임시 저장소에 보존하고 주소에서 제거한다. 카카오 로그인 상태 DB에는 쿼리가 없는 내부 경로만 기록하며, 실패·취소에도 해당 경로로 다시 돌아갈 수 있다. 교체·폐기한 링크와 방장 권한을 잃은 사용자의 과거 발급 요청 재사용을 거부한다.

언어·최대 소요시간·모드는 필수 조건, 장르·난이도는 선호다. 공통 미경험 작품이 없으면 실제 대기 상태를 유지한다. 추천 점수는 장르 일치 2, 난이도 일치 1의 참가자 합이며 동점은 버전 ID순이다. 저장한 후보 순위로 작품 투표 동률을 처리한다. 전원 미투표는 종료한다. 거절자/수락 미응답자는 빠지고 동의한 나머지는 원래 queued_at으로 복귀한다.

차단은 새로운 모집·매칭을 제한한다. 진행 중 역할을 강제로 바꾸거나 타인의 자료를 회수하는 기능으로 사용하지 않는다. 신고는 운영자가 조회할 수 있다.

Discord 음성 모드는 연결 계정이 전용 서버에 가입을 완료해야 한다. 현재 서버 소유자는 참가할 수 있고, 소유자가 아닌 관리자·채널 관리·권한 관리·멤버 이동 권한 계정은 제외한다. 서버 소유자의 Discord 채널 접근 권한은 앱이 제한할 수 없으므로 소유자에게 밀담 채널의 접근 차단을 보장하지 않는다. 웹의 역할·개인 자료·텍스트 밀담 권한은 기존 참가자 규칙을 따른다.

## 자료·대화

| 데이터 | 열람 가능 대상 |
| --- | --- |
| 작품 소개·공개 역할 | 누구나 |
| 모집방 상태 | 실제 참가자 |
| 개인 비밀·목표 | 해당 게임의 본인 역할 |
| 단서 | 소유자, 명시적 공유 수신자, 전체 공개 시 참가자 |
| 전체 메시지 | 발송 당시 참가자 |
| 밀담 메시지 | 발송 당시 해당 밀담 참가자 |
| 결과·개인 목표 | 해당 세션 참가자에게 허용된 엔딩 |

게임 권한을 잃은 사용자는 기존 메시지·자료 API도 사용할 수 없다. 밀담만 나가면 이미 받은 단서·메시지는 볼 수 있지만 새 메시지는 받지 못한다. 공개 작품 버전은 수정하지 않고 새 버전으로 등록한다. 비밀 자료 최초 응답 전에 작품 단위 노출을 저장한다.

## 게임·복구

각 단계 인스턴스에는 시작·종료 시각과 순번을 저장한다. 읽기 단계는 전원 읽기 완료로 일찍 끝낼 수 있다. 조사·투표는 단계 허용 행동과 마감 시각을 확인한다. 같은 대상 재조사는 단서를 추가 지급하거나 횟수를 다시 차감하지 않는다.

샘플 투표는 변경·기권 허용, 미제출은 기권, 동률과 전원 기권은 지목 실패다. 모든 경우 단일 엔딩으로 종료한다. 단계가 바뀌면 열린 밀담과 초대는 종료한다. 단서의 소유권 양도는 제공하지 않는다.

재시작 때 만료된 현재 단계만 종료하고 다음 단계 시간을 현재 시각부터 새로 부여한다. 새로고침으로 역할이 바뀌지 않는다. 120초 유예 동안 자료·역할·투표를 보존한다. 장기 미복귀 판정은 기본 5분이며 그때 연결된 잔여 참가자 전원 동의로 중단한다. 정상 연결 상태에서도 전체 참가자 전원이 중단에 동의할 수 있다. 중단 투표는 60초 유효하다. 전원 30분 미접속은 자동 중단한다.

명시적인 게임 탈퇴는 권한을 회수하고 활동을 해제한다. 기존 역할 행은 남으며 새 참가자를 넣지 않는다. 탈퇴자의 미제출은 기권 처리한다. 완료와 중단은 서로 다른 플레이 기록이다.

WebSocket은 HTTP 세션·허용 Origin·CONNECT CSRF를 검사한다. `/user/queue/events` 이외 구독과 클라이언트 SEND를 거부한다. 로그아웃/만료 연결을 정리하고 재접속·화면 복귀·15초마다 권한별 snapshot을 갱신한다.

## 제작·검수·보드게임

작품 소유자만 초안과 원본 자료를 편집한다. 시스템 작품의 기존 관리자 등록 경로는 작가 작품의 검수를 우회하지 못한다. 초안은 미완성이어도 저장하고 revision 불일치는 409로 거부한다. 검증을 통과한 동일 revision은 동일한 불변 실행 버전으로 고정한다. 검수 재제출은 이전 PENDING을 SUPERSEDED로 바꾸며, 한 번 처리한 요청의 동시 승인을 거부한다. 공개 버전의 definition/presentation은 DB 트리거로도 수정할 수 없다.

자유 테이블은 참가자가 공용 물체를 조작하고 개인 손패는 소유 좌석만 조작한다. 잠긴 물체는 방장이 조작한다. 덱 순서, 상대 손패 앞면, 뒤집힌 공용 카드 앞면은 참가자 DTO에 포함하지 않는다. 자신의 손패는 앞면, 공용 카드는 공개 상태에 맞는 앞면 또는 뒷면, 덱은 공통 뒷면만 제공한다.

카드 디자인이 연결된 면은 `faceDesign` 또는 `backDesign`의 시각 필드만 반환한다. 원본 레이아웃·반대 면·작성용 요소 ID·레이아웃 연결·임의 메타데이터를 반환하지 않으며, 카드의 기존 이름·문구·이미지도 함께 내리지 않는다. 지정된 빈 디자인을 기존 표현으로 대체하지 않는다. 연결이 없는 면만 기존 표현을 사용하며 잘못된 연결은 완전 검증에서 거부한다. 덱 카드를 뽑아도 고정 버전의 앞면과 덱 공통 뒷면 연결을 유지한다.

실제 게임과 가상 좌석 시험은 같은 Java 투영을 사용한다. 게임/샌드박스 문맥의 파일 다운로드도 그 시점의 투영에 포함된 자산인지 확인한다. 카드 전달·공개 상태 변경 후 열람 권한을 다시 계산하며 이전에 정당하게 열람한 내용을 회수한다고 보장하지 않는다. 카드 디자인 자산은 소유권 확인과 불변 버전 참조·삭제 방지 대상에 포함한다. 숨김 레이어는 보안 설정이 아니며 카드의 소유 좌석·공개 상태, 장면의 자료 연결과 역할·단서 권한으로 판단한다.

모든 보드게임 확정 명령은 expectedVersion과 멱등 키를 사용한다. 먼저 커밋된 상태와 다른 버전의 명령은 409로 거부하며 요청 재전송이 주사위나 카드 뽑기를 다시 수행하지 않는다. 드래그 도중 위치는 브라우저 내부 표시이고 놓을 때만 서버에 확정한다. 자유 테이블의 점수와 종료는 수동 기록이며 검증된 경쟁 순위로 사용하지 않는다. 요트형의 점수·보너스·공동 순위·기권 처리는 Java가 계산한다. 자유 오목·리버시·체커는 2인 전용이며 허용 수·자동 패스·연속 포획·승패·무승부·기권도 Java에서 계산한다. [채택 규칙](classic-games.md)을 따른다.

샌드박스는 독립된 가상 좌석 상태이며 app_user·player_activity·Discord를 만들지 않는다. 초대 시험은 실제 회원과 활동 제한을 사용하고 공개 목록·정식 전적에서 제외한다. 머더미스터리 비밀을 조회하면 시험에서도 작품 노출 이력을 남기며, 시험하지 않은 엔딩의 도달 가능성을 보증하지 않는다.


## 시험 엔딩 관찰

Java가 ENDING 진입에서 확정한 엔딩을 작가/검수자 샌드박스 또는 초대 시험 출처로 기록한다. 기록은 상태 변경과 같은 Commands 트랜잭션에서 저장하고 초기화 후에도 보존한다. 정식 게임은 제외하며 버전별 최초 도달만 집계한다. 구조 검증 통과·실제 도달·공개 승인은 별개이고 모든 엔딩 도달은 새로운 공개 조건이 아니다. 전체 엔딩 관찰은 소유자 또는 해당 제출 버전의 유효한 검수 권한자만 조회한다.
