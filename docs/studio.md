# 머더미스터리·보드게임 제작 스튜디오

로그인 후 **제작 스튜디오**의 템플릿 보관함에서 시작 게임을 고르고 **이 템플릿으로 만들기**로 내 작품을 만든다. 머더미스터리·자유 테이블·요트형·자유 오목·리버시·체커의 여섯 유형마다 기본 템플릿과 빈 템플릿이 있어 총 12개를 제공한다. 선택한 템플릿은 독립 초안으로 복사되므로 편집해도 템플릿 원본이나 다른 작가의 작품이 바뀌지 않는다. 기본 공개 게임은 작품 탐색에서 바로 플레이할 수도 있다. PC 편집 화면에서 작품 소개·진행 규칙·장면을 작성하고, 저장 → 검증 → 혼자 시험 또는 초대 시험 → 검수 요청 순서로 진행한다. 관리자는 요청된 버전을 확인하고 승인·수정 요청을 결정한다. 공개된 작품은 기존 작품 탐색·모집방·자동 매칭으로 플레이한다.

## 빈 템플릿으로 시작하기

기본 템플릿은 예시 구성과 문구를 고쳐 쓰는 시작점이고, 빈 템플릿은 그 내용을 직접 채우는 시작점이다. 빈 작품에는 소개 문구가 없고, 요소가 없는 공용 장면 하나와 빈 카드 디자인 목록이 있다. 작품 제목과 게임 유형, 지원 인원, 자동 게임의 엔진·기본 색 설정은 유지한다. 빈 템플릿을 골라도 새로운 자동 게임 규칙을 만들거나 요트·오목·리버시·체커의 고정 규칙을 바꾸지는 않는다.

- **빈 머더미스터리:** PC의 **이야기 흐름**에서 등장인물·진행 단계·단서·조사 장소·엔딩을 추가한다. 등장인물 수를 기본 인원에 맞추고, 조사 장소의 단계·단서를 이름으로 연결한다. **투표 설정**에서 범인 역할을 고르고 역할·단서의 **연결된 자료지 만들기·열기**로 자료를 꾸민다. 사건 규칙이 필요하면 기존 조건·효과 선택 항목으로 설정한다. 처음에는 이 목록들과 범인 역할이 비어 있으며, 투표 변경·기권·동률 처리의 기본 설정은 있다.
- **빈 자유 테이블:** **테이블 배치**에서 카드·말·주사위·카운터·카드 덱을 추가한다. 구성물을 선택하면 이름·문구·이미지·위치를 편집할 수 있다. 카드의 **카드 앞·뒷면 디자인** 또는 **카드 디자인 추가**로 직접 디자인을 만든다. 덱은 카드 앞면과 공통 뒷면을 각각 연결한다.
- **빈 요트·오목·리버시·체커:** **기본 정보**에서 소개를 쓰고 **게임 디자인**에서 색상을 바꾼다. 게임판·초기 말 배치·차례·승패는 기존 Java 엔진이 제공한다. **장면·자료**의 빈 장면에는 안내 문구·이미지·도형을 추가할 수 있다.

빈 상태도 초안 저장과 디자인 미리보기가 가능하다. 소개를 포함한 필수 내용을 채우고 **검증**을 통과해야 시험용 버전 고정과 검수 요청을 할 수 있다. 미리보기는 작성한 화면을 보여 주며 플레이 가능한 작품임을 보증하지 않는다. 모바일에서는 기존 내용 확인·문구·색상·이미지 교체·시험을 사용하고, 첫 구성물 추가와 구조·연결 편집은 PC에서 진행한다.

## 제작 유형

| 유형 | 제작 내용 | 판정 |
| --- | --- | --- |
| 머더미스터리 | 역할·비밀·조사·단서·단계·조건·효과·투표·엔딩·장면 | 기존 Java 규칙 |
| 자유 테이블 | 설명서·공용 카드·덱·카드 앞뒷면 디자인·말·주사위·점수 카운터·배경 | 조작 권한과 난수만 서버 판정, 점수·종료는 수동 |
| 요트형 | 소개·허용 인원·주사위·점수판·장면 디자인 | Java의 고정된 차례·점수·종료 규칙 |
| 자유 오목·리버시·체커 | 소개·게임판·말 색상·장면 디자인 | Java의 착수·포획·차례·승패 규칙 |

자유 테이블과 요트형은 1~4명 중 허용 인원을 정한다. 자유 오목·리버시·체커는 2인 전용이다. 자동 매칭은 그중 2~4명만 사용한다. 혼자 플레이는 직접 1인 방을 만든다. 머더미스터리는 역할 수가 정원과 같아야 한다. 새로운 자동 규칙 게임은 Java 엔진 추가가 필요하며 임의 스크립트·범용 규칙 블록·AI 상대·3D 물리를 지원하지 않는다.

## 편집과 저장

상단의 저장 상태·되돌리기·다시 실행·저장·미리보기·시험 플레이를 사용하고, **공개 준비**에서 검증과 검수 요청을 한다. 작업 단계는 꾸미기 / 게임 설정 / 테스트 / 공개 준비로 나눈다. 작업실의 가변 왼쪽 목록/속성과 중앙 작업 영역에서 자유 테이블은 구성물 배치, 머더미스터리는 이야기 흐름, 자동 규칙 게임은 지원하는 디자인을 편집한다. 소개·규칙·장면·카드 디자인을 오가도 같은 초안과 되돌리기 기록을 사용한다. 기본 공용 장면은 16:9, 역할지·단서 자료는 세로형이다. 텍스트·이미지·도형·자료 요소를 이동·크기 조절·회전·복제·정렬하고 레이어 순서·잠금·숨김을 조절한다. 확대·축소는 편집 화면 표시만 바꾼다. 한글은 속성 입력창이나 캔버스 텍스트를 두 번 눌러 입력하며, 조합 중인 Enter는 적용 명령으로 처리하지 않는다.

편집이 멈추고 2초가 지나면 자동 저장한다. 수동 저장도 가능하다. 미완성 초안은 저장할 수 있지만 시험·검수용 버전을 고정하려면 구조 검증을 통과해야 한다. 다른 창에서 먼저 저장하면 revision 충돌을 표시하며, 로컬 사본을 내려받거나 서버 문서를 다시 불러온다. 서버 문서를 불러오기 전 필요한 사본을 보존한다. 브라우저의 임시 복구 사본에는 비밀 자료도 포함되므로 공용 PC 사용 후 로그아웃한다.

**레이어 숨김은 비밀 보호 설정이 아니다.** 실제 플레이에서는 역할·단서·조사 대상 연결과 현재 단계의 Java 권한으로 요소를 걸러낸다. 비밀 이미지는 해당 자료에 연결한다. 공용 장면에 권한 연결 없이 넣은 내용은 참가자 모두에게 전달된다.

## 자유 테이블과 카드 디자인

테이블 작업 영역은 1000×650이며 실제 공용 카드·말·주사위·카운터를 선택해 옮기거나 크기를 바꾼다. 덱은 위치를 정하고 카드 목록을 편집한다. 장면에 넣은 장식은 실제 플레이 구성물이 되지 않는다. 모바일에서는 구성 확인과 문구·색상·이미지 교체를 중심으로 사용하고 정교한 배치는 PC에서 작업한다.

공용 카드의 **카드 앞·뒷면 디자인**, 덱의 **덱 공통 뒷면 디자인**, 덱 카드의 **이 카드 앞면 디자인**으로 같은 작업실의 카드 편집기를 연다. 텍스트·이미지·사각형·타원을 배치하며, 디자인의 기본 논리 크기는 600×850이다. 덱에서 뽑은 실제 카드의 크기는 120×170이다. 공용 카드는 연결한 디자인의 앞뒷면을 쓰고 덱 카드는 각자의 앞면과 덱에서 지정한 공통 뒷면을 쓴다. 덱에 공통 뒷면 디자인을 연결하지 않으면 기존 덱 뒷면 이미지를 사용하며, 개별 카드 디자인의 뒷면으로 대신하지 않는다.

디자인이 연결된 면에는 그 디자인만 표시한다. 요소를 모두 지운 면은 배경색만 남으며 기존 이름·문구·이미지가 다시 나타나지 않는다. 연결을 해제한 면은 기존 이미지·문구 표시를 사용한다. 같은 디자인을 여러 카드에 연결할 수 있고, 사용 중인 디자인은 연결을 해제한 뒤 삭제한다. 현재 열람할 수 있는 면만 참가자에게 전달하며, 이 검사는 혼자 시험과 실제 플레이에 공통으로 적용한다. [카드 JSON 예제와 화면 구성](studio-ui.md#카드-레이아웃-json-예제), [필드와 검증 범위](scenarios.md#카드-디자인-계약)를 참고한다.

## 파일

자산 보관함은 본인이 업로드한 파일만 보여준다. PNG·JPEG 이미지 10MB, MP3·OGG·WAV 음원 25MB, 작가당 총 512MB까지 사용한다. 이미지 최대 가로·세로 8,192px, 총 1,600만 화소를 검사한다. 원본 파일명이나 요청 MIME만 신뢰하지 않는다. SVG·HTML·외부 실행 코드 업로드는 지원하지 않는다.

편집 초안 또는 고정 버전이 참조하는 파일은 삭제할 수 없다. 파일 주소를 알아도 소유자·검수자·해당 게임 참가자의 현재 열람 권한이 없으면 다운로드를 거부한다. 공개 소개에는 비공개 파일 본문이나 전체 편집 문서를 넣지 않는다.

장면에 BGM 한 곡을 연결할 수 있다. 플레이어가 재생 버튼을 누르면 시작하며 음량·음소거는 개인 설정이다. 모바일에서는 장면을 화면 폭에 맞추고 역할지·단서를 읽기 패널로 연다. 카드는 드래그하거나 선택 후 목적 위치를 지정한다.

## 규칙과 시험

머더미스터리는 기존 조건 ALWAYS·CULPRIT_IDENTIFIED·CLUE_PUBLIC·HAS_CLUE·FLAG·NOT·ALL·ANY, 효과 GRANT_CLUE·PUBLISH_MATERIAL·SET_FLAG를 설정한다. 단계 시작 시 허용 장면 중 기본 장면을 적용하고 방장은 현재 단계에 허용된 다른 장면을 고를 수 있다. 장면 변경은 단계나 자료 열람 권한을 바꾸지 않는다.

자유 테이블은 공용 구성물과 각 자리의 손패 영역을 사용한다. 덱 섞기·뽑기·카드 전달·뒤집기·말 이동·주사위·수동 점수·차례 표시를 지원한다. 자신의 손패만 조작할 수 있고 잠긴 공용 물체는 방장만 조작한다. 다른 사람의 손패 앞면과 덱 순서는 서버 응답에서 제거한다. 놓은 위치만 서버에 확정하며 충돌은 최신 상태를 확인한 뒤 다시 조작한다. 방장이 종료한 결과는 수동 기록으로 취급한다.

요트형은 6면 주사위 5개를 차례마다 최대 세 번 굴린 뒤 사용하지 않은 점수 칸 하나를 확정한다. 숫자별 합계 6칸과 CHOICE·FOUR_KIND·FULL_HOUSE·SMALL_STRAIGHT·LARGE_STRAIGHT·YACHT, 총 12칸이다. 포카드는 4개 이상 같은 눈의 전체 합, 풀하우스는 정확한 3+2의 전체 합, 연속 네 눈은 15점, 다섯 눈은 30점, 같은 눈 다섯 개는 50점이다. 숫자별 합계가 63점 이상이면 보너스 35점이다. 조건 불일치 칸에 0점을 기록할 수 있으며 확정 점수는 변경할 수 없다. 모두 12칸을 채우면 총점으로 공동 순위를 계산한다. 기권자는 이후 차례에서 제외하고 1인은 점수 도전이다.

혼자 시험은 가상 역할·좌석을 전환하며 같은 서버 상태를 사용한다. 머더미스터리의 역할별 자료 비교는 각 자리의 서버 응답을 나란히 표시하며, 현재 열람할 수 있는 단서와 비밀만 해당 카드에 보여준다. 머더미스터리는 시간을 진행할 수 있고 전체 초기화도 가능하다. 가짜 회원·매칭·Discord를 만들지 않는다. 초대 시험은 고정한 미공개 버전에 실제 회원이 참가한다. 정원·준비·활동 중복 정책은 실제 게임과 같고 정식 전적에는 포함하지 않는다. 머더미스터리 비밀을 본 이력은 시험에서도 남는다. 보드게임 반복 참가에는 노출 이력을 적용하지 않는다.

고전 게임의 세부 규칙과 제작 자료 기준은 [클래식 보드게임 안내](classic-games.md)를 따른다.

구조 검증 통과는 엔딩의 실제 도달 확인을 의미하지 않는다. 시험한 분기와 아직 확인하지 않은 분기를 구분해서 검수한다.

## 검수와 공개 버전

제출하면 그 revision의 규칙·장면·카드 디자인·파일 참조를 불변 버전으로 고정한다. 새 수정본을 제출하면 이전 검수 요청은 대체된다. 관리자가 승인할 때 현재 초안이 아니라 제출된 정확한 버전을 공개한다. 이미 공개된 버전은 새 버전 승인 전까지 유지되고 진행 중인 방과 게임은 처음 선택한 버전을 계속 사용한다. 이후 초안에서 카드 앞면이나 공통 뒷면을 바꿔도 이미 고정한 시험·공개 버전은 바뀌지 않는다.

## API 경계

- `/api/v1/author/templates`: 기본·빈 템플릿의 소개·인원·수정 가능 항목·규칙 요약과 빈 템플릿 여부(`blank`). 생성 요청의 `templateId`로 선택한다.
- `/api/v1/author/works`: 내 작품 목록·생성·조회·revision 저장, `/validate`·`/freeze`·`/submit`·`/test-room`.
- `/api/v1/author/assets`: 자산 목록·업로드·삭제. `/api/v1/assets/{id}`: 게임 또는 샌드박스 문맥을 검사하는 파일 다운로드.
- `/api/v1/author/sandboxes`: 고정 버전의 가상 좌석 시험 생성·조회·명령.
- `/api/v1/admin/scenario-reviews`: 관리자 검수 목록·제출 문서·결정.
- `/api/v1/games/{id}/kind`, `/board-snapshot`, `/board-commands`, `/scene`: 유형별 권한 응답과 서버 명령.

게임 명령은 세션·CSRF·Idempotency-Key를 사용한다. 보드게임 명령은 expectedVersion도 포함한다. 멱등 저장에는 비밀 snapshot을 넣지 않는다. 정확한 요청·응답은 `docs/openapi.json`과 생성 타입을 따른다.


## 여러 오류 확인과 이전 버전 시험

검증은 `{valid, issues, revision, truncated}`를 반환한다. 각 이슈는 실제 필드 `path`, `code`, `message`, `severity`를 포함한다. 같은 Java 검사 조건으로 여러 오류를 모으며 잘못된 자료형의 하위 검사만 중단한다. 최대 100개까지 표시하고 추가 오류가 있으면 `truncated: true`다. 오류를 누르면 해당 카드 면·요소·입력으로 이동한다. 검증 뒤 편집·되돌리기·정렬·삭제하면 이전 결과로 표시하고 위치 이동을 막는다. 다시 검사하면 새 개정 기준 결과로 바뀐다. 동결·검수 요청·승인은 여전히 엄격한 전체 검사를 통과해야 한다.

공개 준비의 **버전과 검수 → 내용 보기 · 이 버전 시험**에서 불변 문서와 고정 당시 개정을 확인한다. 그 버전의 허용 인원·대화 방식으로 혼자 또는 초대 시험을 시작하며 초안을 덮어쓰거나 다시 고정하지 않는다. 초대 시험으로 화면을 나갈 때 현재 초안 저장을 먼저 확인한다. 혼자 시험을 끝내면 기존 편집 위치로 돌아간다. 검수자도 제출 버전의 허용 인원을 고를 수 있다.

### 실제 도달한 엔딩

엔딩 기록은 Java 엔진이 시험 실행에서 ENDING 단계의 엔딩을 확정한 때 저장한다. 작가 혼자 시험, 검수자 혼자 시험, 실제 회원의 초대 시험을 각각 구분해 최초 도달 시각을 보여준다. 동일 버전의 모든 시험을 합쳐 `시험에서 도달한 엔딩 2/4`와 같이 표시한다. 초기화·중단 후에도 유지하고 재전송은 중복 기록하지 않는다. 새 버전은 새 기록을 가지며 이전 시험을 소급 완료 처리하지 않는다. 정식 게임은 포함하지 않는다.

구조 검사·실제 엔딩 도달·관리자 승인은 별개다. 기록 없는 엔딩을 도달 불가능으로 판단하지 않고, 모든 엔딩 시험을 공개 필수 조건으로 추가하지 않는다. 전체 엔딩 목록은 작품 소유자와 해당 버전의 유효한 검수 권한자만 조회한다. 초대 참가자는 이 목록 API를 사용할 수 없다.

추가 API:

- `GET /api/v1/author/works/{workId}/versions/{versionId}`: 소유권과 작품/버전 관계를 확인한 작가용 불변 문서. `workId`, `versionId`, `version`, `authorRevision`, 상태·검수 상태·의견·`document`를 반환한다. 검수자는 기존 관리자 경로를 사용한다.
- `GET /api/v1/author/versions/{versionId}/ending-observations`: `versionId`, `authorRevision`, `totalEndings`, `reachedEndings`, `endings`를 반환한다. 각 엔딩은 `endingId`, `title`, `authorReachedAt`, `reviewerReachedAt`, `invitedTestReachedAt`를 가지며 미도달 시각은 `null`이다. 보드게임은 엔딩 목록과 개수가 비어 있다.

검증 응답 예시(개정 번호와 메시지는 예시):

```json
{
  "valid": false,
  "revision": 7,
  "truncated": false,
  "issues": [
    {"path":"presentation.cardLayouts.0.back.nodes.0.width","code":"INVALID_PRESENTATION","message":"숫자 값의 허용 범위를 확인해 주세요.","severity":"ERROR"}
  ]
}
```

DB의 V10은 `sandbox_ending_observation`과 `invited_test_ending_observation`을 추가한다. 실행 FK와 중복 방지 제약, 초대 시험의 `(game_id,is_test)` 복합 FK를 사용하며 버전은 부모 실행에서 연결한다. 엔딩 관찰 저장과 게임 상태 변경은 동일 Commands 트랜잭션이다. 실행 버전·진행 중 게임·기본/빈 템플릿 12개의 정의는 다시 작성하지 않는다.
